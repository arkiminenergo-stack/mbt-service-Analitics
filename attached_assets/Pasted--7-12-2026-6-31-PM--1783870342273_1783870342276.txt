[7/12/2026 6:31 PM] Михаил Раевский: Создание прототипа интеллектуальной проверки комплектности документов

Цель:
Разработать веб-приложение на Flask, которое загружает пакет документов (PDF или изображения), распознаёт их, классифицирует, извлекает ключевые данные и проверяет комплектность по заданному шаблону (для процесса выдачи субсидии). Результат — отчёт о полноте и согласованности данных.

Технологии и библиотеки (должны быть установлены через pyproject.toml или requirements.txt):

· Flask (веб-фреймворк)
· OpenCV-Python (предобработка изображений)
· pytesseract (OCR, движок Tesseract)
· pdf2image (конвертация PDF в изображения, потребуется poppler-utils — установи через apt в Replit)
· NumPy
· python-Levenshtein (для нечёткого сравнения строк)
· Werkzeug (для безопасной загрузки файлов)

Структура проекта (создай файлы):
/prototype
├── app.py                 # основной Flask-сервер
├── ocr_engine.py          # логика OCR и предобработки
├── classifier.py          # классификатор типа документа
├── extractors.py          # извлечение полей для каждого типа
├── validator.py           # проверка комплектности и кросс-валидация
├── templates/

├── static/                # CSS/JS (минимум)

├── requirements.txt
└── .replit                # (опционально) команда запуска

Пошаговый план реализации

Шаг 1. Инициализация проекта и установка зависимостей

· Создай структуру папок.
· В requirements.txt пропиши все перечисленные библиотеки.
· В .replit укажи run = "python app.py".
· В начале app.py или в отдельном скрипте автоматически проверяй наличие tesseract и poppler-utils. Если возможно, выполни команду apt-get update && apt-get install -y tesseract-ocr tesseract-ocr-rus poppler-utils (для русскоязычного OCR). В Replit это можно сделать через файл replit.nix или при первом запуске.

Шаг 2. Веб-интерфейс загрузки (app.py + upload.html)

· Создай Flask-приложение с одним маршрутом / (GET — показ формы, POST — обработка).
· Форма в upload.html должна позволять загрузить несколько файлов (поле <input type="file" multiple>).
· Файлы сохраняются в папку uploads/ с уникальными именами (используй werkzeug.utils.secure_filename).
· После загрузки запускается основной пайплайн обработки, результат рендерится в report.html.

Шаг 3. OCR и предобработка (ocr_engine.py)

· Функция process_document(filepath) -> (list of images, list of extracted texts with bounding boxes):
  · Если файл PDF: конвертировать каждую страницу в изображение через pdf2image.convert_from_path().
  · Если изображение (jpg, png): загрузить как есть.
  · Для каждого изображения выполнить предобработку:
    · Конвертация в оттенки серого.
    · Адаптивная бинаризация (cv2.adaptiveThreshold с методом Гаусса) для улучшения читаемости.
    · Удаление шума медианным фильтром.
  · Пропустить изображение через pytesseract с параметрами --oem 3 --psm 6 -l rus+eng, получая текст и данные о словах/блоках (pytesseract.image_to_data).
  · Вернуть список страниц и детальную информацию.

Шаг 4. Классификация типа документа (classifier.py)

· Функция classify_document(text: str) -> str:
  · Используй простой keyword-based классификатор. Собери словари ключевых слов для каждого типа:
    · passport: "паспорт", "серия", "номер", "гражданство"
    · income_statement (справка 2-НДФЛ): "2-ндфл", "доход", "налоговый агент", "инн"
    · application (заявление): "заявление", "прошу", "субсидия", "компенсация"
    · bank_details (реквизиты счёта): "расчётный счёт", "бик", "банк"
    · unknown – если ни одно не подошло.
  · Поиск должен быть нечувствителен к регистру. Если набрано определённое количество совпадений (например, 2), возвращаем тип. Иначе unknown.

Шаг 5. Извлечение структурированных полей (extractors.py)

· Для каждого известного типа напиши отдельную функцию-экстрактор, использующую регулярные выражения на основе OCR-текста и позиционирования (если доступно из pytesseract, то ищем по близости к ключевому слову).

Используй паттерны: "серия" — 4 цифры, "номер" — 6 цифр, строки с ФИО и т.д. Учти, что в паспорте РФ ФИО обычно в формате «Фамилия Имя Отчество».
  · extract_income_data(pages_data) – возвращает inn, total_income, tax_period. Для поиска ИНН (10 или 12 цифр), годового дохода (число с разрядами) и периода.
  · extract_application_data(pages_data) – возвращает full_name (ФИО из заявления), purpose (первые 100 символов после «прошу предоставить»).

· Все экстракторы возвращают словарь и флаг уверенности (например, True если основные поля найдены без противоречий). Если поле не найдено — значение None.

Шаг 6. Валидация комплектности и кросс-сравнение (validator.py)

· Функция validate_package(documents: dict) -> dict, где documents — это словарь вида {type: extracted_data}.
· Шаблон комплектности для процесса «Субсидия» (можно задать константой в коде):
  · Обязательные типы документов: passport, income_statement, application, bank_details.
  · Внутри каждого типа обязательные поля:
    · passport: все поля обязательны.
    · income_statement: inn, total_income.
    · application: full_name, purpose.
    · bank_details: account_number, bik.
· Логика проверки:
  1. Проверка наличия всех типов. Отсутствующие помечаются как «Не предоставлен».
  2. Проверка заполнения обязательных полей в каждом документе.
  3. Кросс-документная сверка (если поля совпадают):
     · full_name из заявления должно нечётко совпадать с комбинацией ФИО из паспорта (используй расстояние Левенштейна, допуск 2-3 ошибки).
     · inn из справки должен совпадать с ИНН, если бы он был в паспорте (но в паспорте нет ИНН — можно пропустить или сравнивать с заявлением, если там есть).
     · Здесь достаточно сверки ФИО и, если возможно, серии/номера паспорта с заявлением (при наличии такого поля).
· Возвращаемый словарь должен содержать:
  · status: "complete" или "incomplete".
  · missing_docs: список отсутствующих типов.
  · errors: список строк с описанием каждой проблемы (например, "В справке 2-НДФЛ не указан ИНН", "ФИО в заявлении не совпадает с паспортом").
  · extracted_data: обобщённый словарь со всеми данными (для отладки/просмотра).

Шаг 7. Интеграция и вывод результатов (app.py + report.html)

· После получения файлов выполняй последовательно:
  1. Для каждого файла вызывай process_document, склеивай текст всех страниц.
  2. Классифицируй (classify_document). Если тип unknown — в отчёт записывай предупреждение.
  3. Вызови соответствующий экстрактор для этого типа.
  4. Сформируй общий словарь documents = {тип: данные}, где ключ — тип документа. Если было загружено несколько документов одного типа (например, два паспорта) — обрабатывай как конфликт или бери первый.
  5. Вызови validate_package(documents).
· Результат передай в шаблон report.html.
· В report.html отобрази:
  · Общий статус (зелёный/красный).
  · Таблицу с каждым загруженным файлом: оригинальное имя, определённый тип, извлечённые поля (ключ-значение).
  · Список ошибок, если есть.
  · Для наглядности, где поле не найдено, выводи "Нет данных".
