# Система автоматизированной проверки документов

## Назначение

Универсальная система для автоматизированного анализа, структурирования и верификации пакетов документов. Предназначена для организаций, работающих с большими объёмами разнородных документов: юридических дел, договорных пакетов, контрольных проверок, аудитов, исполнительного производства и иных документальных процессов.

Система автоматически извлекает структурированные данные из сканов и машиночитаемых документов, выявляет связи между документами, организует их в иерархические структуры и формирует аналитические отчёты. Искусственный интеллект выступает исключительно как оркестратор и конфигуратор — вся обработка данных выполняется детерминированными алгоритмами для обеспечения максимальной точности и воспроизводимости результатов.

---

## Текущий функционал

### 1. Управление проектами

Документы группируются в проекты. Каждый проект представляет собой замкнутый рабочий контекст — отдельное дело, проверку, аудит или иной процесс.

- Создание, переименование и удаление проектов
- Группировка документов внутри проекта по документальным пакетам (папкам загрузки)
- Индикация статуса обработки каждого документа
- Ролевое разграничение доступа

### 2. Загрузка и предобработка документов

- Загрузка документов в форматах PDF, DOCX, XLSX через веб-интерфейс
- Загрузка ZIP-архивов с автоматическим извлечением файлов (поддержка кодировок CP1251/CP866 для русскоязычных имён файлов)
- Конвертация DOCX и XLSX в PDF через LibreOffice (headless) для единообразного отображения
- Хранение оригиналов и конвертированных версий

### 3. Обработка сканированных документов (OCR)

Поддержка двух режимов:

**Машиночитаемые PDF** — прямое извлечение текста через pdfplumber без потери качества.

**Сканы (растровые PDF)** — полноценный OCR-конвейер:
1. Определение ориентации страницы (0°/90°/180°/270°) через Tesseract OSD
2. Автоматическая коррекция поворота
3. Коррекция наклона (deskew) через OpenCV
4. Генерация searchable PDF — документ с невидимым текстовым слоем поверх изображения скана
5. Извлечение текста с разбивкой по страницам

Результат — searchable PDF корректно отображается в просмотрщике с правильной ориентацией и поддерживает выделение/копирование текста.

### 4. AI-анализ содержимого

Гибридный подход: сначала быстрые алгоритмические методы, затем LLM для сложных случаев.

**Алгоритмическое извлечение (regex + структурный анализ):**
- Даты в форматах dd.MM.yyyy, d MMMM yyyy г. и других вариантах
- Суммы и реквизиты (ИНН, БИК, номера счётов)
- Номера дел, договоров, исходящих/входящих писем
- Наименования сторон

**LLM-анализ (Ollama / OpenAI):**
- Извлечение печатей, подписей, дат подписания
- Смысловой анализ содержимого страниц
- Идентификация типа документа

**Кэширование результатов:** повторный анализ использует сохранённые результаты без повторного вызова LLM.

### 5. Просмотр документов

Встроенный PDF-просмотрщик на базе React-PDF / PDF.js:
- Постраничное отображение с масштабированием
- Подсветка найденных артефактов (даты, суммы, подписи, печати) прямо в тексте документа
- Панель аннотаций с перечнем всех находок
- Навигация между страницами
- Клик по артефакту в панели → прокрутка к соответствующему месту в документе

### 6. Верификация и статусы

- Ручное утверждение или отклонение каждого найденного артефакта
- Статусы файлов: не обработан / обрабатывается / завершён / ошибка
- Фильтрация файлов по статусу верификации

### 7. Экспорт

- Выгрузка результатов анализа в XLSX с детализацией по файлам и артефактам
- Сводные данные по проекту

## Планируемый функционал

### 8. Иерархическая структура документов (папки)

Возможность создавать папки и подпапки внутри проекта для логической группировки документов по типу, стороне, хронологии или иному критерию.

**Структура папки:**
- Название и описание
- Цветовая метка и иконка для визуального различения
- Вложенные подпапки (произвольная глубина)
- Признак создания: вручную пользователем или автоматически агентом

**Операции:**
- Создание, переименование, перемещение, удаление папок
- Перемещение файлов между папками (drag & drop)
- Один файл может находиться в нескольких папках одновременно (логические ссылки, не копии)

**Алгоритмическое распределение файлов по папкам** — агент формирует правила, алгоритм исполняет:

```
Правила классификации (пример для юридических дел):
├── Содержит "претензия", "досудебная" → папка "Претензии"
├── Содержит "исковое заявление"        → папка "Судебные акты / Первая инстанция"
├── Содержит "постановление", "апелля"  → папка "Судебные акты / Апелляция"
├── Содержит "договор", "соглашение"    → папка "Договоры"
└── Не подошло ни одно правило          → папка "Без категории"
```

Правила задаются как JSON-конфиг, создаются агентом или вручную пользователем.

### 9. Дерево связей между документами

Автоматическое и ручное построение графа связей между документами проекта.

**Типы связей:**
| Тип | Описание |
|-----|----------|
| `same_case` | Относятся к одному делу/процессу |
| `precedes` | Документ А предшествует документу Б хронологически |
| `responds_to` | Документ является ответом/реакцией на другой |
| `references` | Документ ссылается на другой внутри текста |
| `amends` | Документ вносит изменения в другой |
| `contradicts` | Документы содержат противоречащие данные |
| `same_party` | Документы относятся к одной стороне/субъекту |

**Алгоритмы автоматического обнаружения связей:**

1. **По номеру дела** — regex-поиск стандартных форматов номеров (арбитражные, судебные, административные); все документы с совпадающим номером → `same_case`

2. **По датам и сторонам** — извлечённые наименования + даты сравниваются между документами; совпадение сторон → `same_party`

3. **По иерархии ключевых слов** — словарь типов документов с их логической последовательностью (претензия → иск → решение → апелляция → постановление) → `precedes`

4. **По внутренним ссылкам** — поиск паттернов типа «во исполнение решения от 01.01.2025», «согласно договору №123» с последующим поиском соответствующего документа → `references`

5. **По реквизитам** — совпадение ИНН, БИК, номеров счётов, регистрационных номеров между документами → `same_party`

**Атрибуты связи:**
- Тип связи
- Уверенность алгоритма (0–100%)
- Доказательная база (какое поле совпало, значение)
- Источник: алгоритм / агент / пользователь вручную
- Пользовательская метка/комментарий

---

### 10. Визуализация связей

**Режим «Список»:** иерархический список связей по каждому документу с указанием типа и уверенности. Фильтрация по типу связи.

**Режим «Граф»:** интерактивный граф на базе React Flow:
- Узлы = документы (цвет по типу/папке, размер по количеству связей)
- Рёбра = связи (стиль линии по типу, толщина по уверенности)
- Drag & zoom навигация
- Клик по узлу → открытие документа в просмотрщике
- Клик по ребру → детали связи
- Фокус на выбранном документе с затемнением несвязанных узлов
- Фильтрация: скрыть слабые связи (порог уверенности)

**Панель навигации по связям в просмотрщике:** при открытии любого документа рядом появляется панель со списком всех связанных документов, сгруппированных по типу связи. Клик → немедленное переключение на связанный документ без возврата к списку.

### 11. AI-агент с инструментами

Чат-интерфейс, в котором пользователь ставит задачи на естественном языке. Агент (LLM) принимает решения о том, какие инструменты вызывать и в каком порядке. Вся реальная обработка данных выполняется детерминированными алгоритмическими функциями — LLM не интерпретирует документы напрямую.

**Инструменты агента:**

```
Управление папками:
  createFolder(name, parentId?, description, icon, color)
  renameFolder(folderId, newName)
  moveFolder(folderId, newParentId)
  deleteFolder(folderId, moveFilesTo?)

Управление файлами:
  assignFileToFolder(fileId, folderId, reason)
  moveFile(fileId, fromFolderId, toFolderId)
  getFileMetadata(fileId)
  searchFiles(query)
  listFiles(folderId?)

Связи:
  createRelation(sourceId, targetId, type, evidence)
  deleteRelation(relationId)
  getRelationTree(fileId, depth?)
  findRelatedFiles(fileId)
  runAutoLink(projectId, rules[])

Сценарии:
  createScenario(name, steps[])
  runScenario(scenarioId, fileIds[])
  suggestScenario(userGoal)

Отчёты:
  generateReport(type, scope, format)
  listReportTemplates()

Аналитика:
  analyzeProject(projectId)
  detectDuplicates(projectId)
  findOrphans(projectId)
```

**Формат взаимодействия:**
- Агент анонсирует план действий перед исполнением
- Каждый выполненный шаг отображается в реальном времени
- Агент предлагает варианты (кнопки быстрого ответа) для типовых задач
- История всех диалогов сохраняется

**Примеры типовых задач:**
- «Разложи все документы по папкам»
- «Найди все связанные документы и построй дерево»
- «Что в проекте не обработано?»
- «Создай хронологию событий по проекту»
- «Найди противоречия между документами»
- «Сформируй реестр документов»

### 12. Сценарии обработки

Сохраняемые конфигурации алгоритмического конвейера. Агент создаёт сценарий, пользователь утверждает, движок исполняет детерминированно.

**Структура сценария (JSON):**

```json
{
  "name": "Название сценария",
  "description": "Что делает",
  "trigger": "manual | on_upload | scheduled",
  "steps": [
    {
      "type": "regex_extract",
      "pattern": "...",
      "field": "case_number"
    },
    {
      "type": "date_extract",
      "formats": ["dd.MM.yyyy", "d MMMM yyyy г."]
    },
    {
      "type": "keyword_classifier",
      "rules": [
        { "keywords": ["..."], "folder": "..." }
      ]
    },
    {
      "type": "auto_link",
      "match_field": "case_number",
      "relation_type": "same_case"
    },
    {
      "type": "sort_by_date",
      "date_field": "document_dates",
      "build_relation": "precedes"
    },
    {
      "type": "generate_report",
      "template": "timeline",
      "format": "xlsx"
    }
  ]
}
```

**Шаги сценария:**
| Тип шага | Описание |
|----------|----------|
| `regex_extract` | Извлечение поля через регулярное выражение |
| `date_extract` | Извлечение дат в разных форматах |
| `keyword_classifier` | Определение папки по ключевым словам |
| `auto_link` | Создание связей по совпадению поля |
| `sort_by_date` | Хронологическая сортировка с созданием связей |
| `generate_report` | Формирование отчёта по результатам |
| `flag_missing` | Пометка документов с отсутствующими полями |
| `cross_validate` | Сверка полей между связанными документами |

### 13. Отчёты

**Шаблоны отчётов:**

| Шаблон | Содержание | Формат |
|--------|-----------|--------|
| Реестр документов | Все документы с метаданными, папками, статусами | XLSX |
| Хронология событий | Документы отсортированы по дате, с описанием | XLSX / PDF |
| Дерево связей | Граф связей с описанием каждой | PDF |
| Сводка по проекту | Статистика: обработано/не обработано, типы, найденные данные | XLSX |
| Сверка данных | Несоответствия и противоречия между документами | XLSX |
| Недостающие документы | Ожидаемые, но отсутствующие документы (по правилам сценария) | XLSX |

Шаблоны расширяются агентом через инструмент `createReportTemplate`.

## Поэтапный план разработки

### Этап 1 — Папки и файловый менеджер
Создание таблиц `document_folders` и `file_folder_assignments`. Реализация CRUD API. Обновление UI проекта: файловый менеджер с деревом папок, перетаскивание файлов.

### Этап 2 — Связи между документами
Создание таблицы `document_relations`. Реализация алгоритмов автосвязывания (5 правил). Панель связей в просмотрщике. Режим «Список» на вкладке «Связи».

### Этап 3 — Граф связей
Интеграция React Flow. Интерактивная визуализация дерева документов. Навигация по графу с открытием документов.

### Этап 4 — AI-агент
Реализация чат-интерфейса. Подключение OpenAI function calling / Ollama tool use. Регистрация всех инструментов агента. Сохранение истории диалогов.

### Этап 5 — Сценарии
Движок исполнения сценариев (JSON → последовательный вызов шагов). UI создания и управления сценариями. Интеграция с агентом (агент создаёт сценарии через инструмент).

### Этап 6 — Расширенные отчёты
Шаблоны отчётов. Генератор хронологии, реестра, дерева связей. Кастомные шаблоны через агента.

## Конфигурация развёртывания

- Тип: autoscale (Node.js + Python сервисы)
- Команда сборки: `npm run build`
- Команда запуска: `node dist/index.js`
- Порт: 5000
- Переменные окружения:
  - `DATABASE_URL` — строка подключения PostgreSQL (обязательно)
  - `OPENAI_API_KEY` — ключ OpenAI API (опционально, для GPT-моделей)
  - `OLLAMA_API_URL` — URL Ollama-сервера (опционально, для локальных моделей)
